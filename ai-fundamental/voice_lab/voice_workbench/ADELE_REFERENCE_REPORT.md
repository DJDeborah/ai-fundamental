# Adele 参考获取与第一轮真实试转

2026-10-03。用户没有目标参考，已按请求从原始发布方取得实际访谈/短清唱，定位到 Adele 的回答或现场演唱。它们是**有出处的版权参考**，没有发现它们属于开放授权音库；完整采访、字幕、ASR 转写、参考 WAV 保存在本机忽略目录。公开演示仅包含用户已有原声和 AI 生成的转换小样。

## 2. 已实际跑过模型

输入固定为已有本人 8 秒清唱。五次准备后的源 WAV SHA256 相同：`1702b4b2a27a3747859f284884cd5d913a1a1733b8ce8bd080b7469686d7c0f3`。采用已固定官方 OpenVoice V2 converter、CPU、seed 1234、LERP、同一源内容编码器和解码器。插值发生在参考音色向量，没有叠加原声和输出波形。

第一次包括重新启动服务后的库/模型加载，不能与后四次当作同条件速度对照。这不是重复测量的速度 benchmark。Vogue 清唱 α=1 的请求从实际浏览器界面发起；另四次经本地 multipart HTTP 接口，输出与收据 SHA256 一致。第一次本人参考使用本次输入，另外四次使用独立本人清唱参考（实际 9.406675 秒）；α=1 的本人端权重为零。

α=0.5 是模型音色向量参数，**不代表听感上本人/Adele 各占 50%**。这批全部源输入是清唱，尚未测试用户新的讲话录音，也未验证 OpenVoice 对旋律与歌声身份的保留。未提供相似度评分、自然度评分或“比旧模型更好”的听评结论。

本轮是**零样本参考条件推理，没有训练或微调**，没有启动新付费 GPU 任务。有限波形和可播放只是运行验证；用户听评才决定这一版本是否解决噪声、多声部和身份相似度问题。

## 3. 现在如何体验

本机运行 `app.py`，打开 http://127.0.0.1:8872/ 。在「本机内置候选」选择 NPR 连续访谈或 Vogue 现场清唱；先点「载入现有 8 秒清唱」，再「生成并试听」。也可录制或上传自己的 5–15 秒讲话；不必自己寻找 Adele 文件。

先测试 α=1，再测 α=0.5；分别听是否有电流声、双声部、歌词或语调损坏。用「本人重建诊断」检查模型基础重建；普通 α=0 是原声旁路。录音停止后才转换，尚未实现持续实时监听。

五个输出与完整私有收据位于 `benchmarks/adele_reference_exploration/`。来源参考及所有定位证据位于 `assets/adele_private_reference/`。这些私有目录不自动发布。可携带播放的生成小样由 `build_adele_demo.py` 从固定白名单构建，不复制采访或字幕。

## 4. 背景音乐分离可以做，但验收标准要分清

[Demucs 官方](https://github.com/facebookresearch/demucs)提供 drums/bass/other/vocals 分离。它能用于取得歌曲中的 vocal stem，vocals 不等于只含目标主唱：和声、混响及其他人声可能一起保留，处理也可能产生金属声和残留。`--two-stems vocals` 不是只运行半个模型。

当前已有无需分离的短参考候选，**本轮没有运行 Demucs，也没有把这些文件称为已去 BGM 的干净人声**。若试听发现伴奏污染，再做同一片段的「原参考 / 分离参考」配对试转，检查身份相似度、歌词清晰度、旋律、噪声与多声部感；只在改善被确认后使用分离结果。

OpenVoice 先用于验证录音入口和音色插值机制。歌声质量仍应后续用 SoulX-Singer-SVC 或 Seed-VC 等有歌声音高处理的模型在同一输入上对照。当前收集的是几段短参考，不是足够训练稳定专属歌手模型的数据集。
